# 智能体（Agent）

> 所属章节：07-AI与大模型基础 ｜ 建议学习时长：1.5 小时 ｜ 难度：⭐⭐☆

## 一句话理解

Agent = 大模型（大脑）+ 工具（手脚）+ 循环（自主性）：给它**目标**而不是步骤，它自己规划、调用工具、观察结果、不断迭代，直到完成任务。

## 直观解释

普通的大模型对话像**问路**：你问一句，它答一句，结束。Agent 像**代驾司机**：你只说"送我回家"，它自己决定路线——先看导航（获取信息）、再打方向盘（执行操作）、发现堵车就换路线（根据反馈调整），直到你到家。

三个要素缺一不可：

| 要素 | 对应 | 缺了会怎样 |
|------|------|-----------|
| 大脑 | 大模型的推理与决策 | 有工具不会用，有循环不会想 |
| 手脚 | 工具（搜索、写文件、调 API…） | 只会"说"，不会"做" |
| 循环 | 思考→行动→观察→再思考 | 做一步就停，无法完成多步任务 |

## 数学定义

Agent 没有严格的数学公式，其结构通常抽象为一个**循环过程**（业界最经典的模式叫 ReAct：Reason + Act）：

```
循环直到任务完成或达到步数上限：
    思考（Reason）：观察当前状态，决定下一步做什么
    行动（Act）：  调用某个工具，作用于环境
    观察（Observe）：获取工具返回结果，更新状态
```

- **状态**：包含目标、已完成步骤、工具返回的结果
- **终止条件**：任务完成（如得到最终答案）、无法继续（失败）、达到最大步数（防止死循环）

## Python 实战

以下结果由 `智能体-示例.py` 实际运行得出——一个规则驱动的迷你 Agent，用三个工具（加、乘、减）分三步算出 `(23+17)*2-8`：

```
目标: 计算 (23+17)*2-8
[第1步·思考] 括号内发现 23+17，选用加法工具
[第1步·行动] 调用 tool(a=23, b=17)
[第1步·观察] 工具返回 40，表达式变为 40*2-8
[第2步·思考] 表达式中发现 40*2，选用乘法工具
[第2步·行动] 调用 tool(a=40, b=2)
[第2步·观察] 工具返回 80，表达式变为 80-8
[第3步·思考] 表达式中发现 80-8，选用减法工具
[第3步·行动] 调用 tool(a=80, b=8)
[第3步·观察] 工具返回 72，表达式变为 72
任务完成！共执行 3 步，最终答案 = 72
```

**解读**：注意每一轮里"思考"的依据是上一轮"观察"到的结果（第 2 步能算 40\*2，是因为第 1 步观察到了 40）——这种**用行动结果驱动下一步决策**的循环，正是 Agent 区别于普通问答的本质。

## 常见误区

1. **"Agent 就是更聪明的聊天机器人"** —— 不对。聊天机器人一问一答就结束；Agent 有循环，能连续行动并根据反馈自我修正。判断标准：它是"说完了"还是"做完了"。
2. **"Agent 是全自动、不会出错的"** —— 恰恰相反，每一步都可能有误差，多步任务会**累积**误差。所以真实的 Agent 系统都要设最大步数、结果校验等"安全带"。
3. **"Agent 一定需要很智能的大脑"** —— 本例的"大脑"只是几条正则规则，但循环结构是完整的。智能决定上限，**结构决定下限**。

## 与其他概念的联系

- 前置知识：大模型基础（大脑的推理能力）、提示词（下达目标的方式）
- 后续延伸：多智能体协作（多个 Agent 分工）、工具调用协议（如 MCP）
- 对比易混：**工作流**（把步骤写死，机器照做）vs **Agent**（只给目标，步骤自己定）。本仓库"生成学习资料三件套"的技能就是工作流和 Agent 的结合——流程固定（工作流），执行细节灵活（Agent）。
